# DreamWaQ 碰撞计数溢出诊断与修复

2026-10-24

服务器约878轮时平均奖励为-1793，最近100轮均值约-4223。主要异常项为 Episode_Reward/linear_z（约-200），其余多数惩罚绝对值小于0.3。该项惩罚的是机身坐标系竖直速度平方，而非世界高度。

安装的 mujoco_warp 3.5 collision_driver.py 在 sap_broadphase 中对全部 world 的候选范围作 int32 前缀和；_sap_broadphase 再在该前缀和上二分查找。原地形10×20包含约12580个几何体，单个world约350万扫描候选，4096个world合计约144亿，确定超过int32最大值约21.47亿。即使不计任何机器人相关候选，静态地形的候选也足以溢出。累计和失去单调性后会破坏碰撞遍历；这强烈指向遗漏接触和异常下落，但服务器原进程没有被插入状态探针，因果链需同规模修复运行进一步验证。

本机较小地形的随机动作和服务器800轮检查点推理没有出现相同异常。服务器4096环境的原地形无法在本机8GB显卡完整复现；完整CPU场景用于计数分析，本机GPU实际运行了修复后1024环境、150步。

修复仅减少地形patch数量：训练网格由10×20改为5×10，仍保留4096并行环境、七种地形及其比例、高度范围、奖励权重和网络结构。课程离散层级从10减到5；初始maxlevel从1改为0，保持初始难度区间约0..0.2。四足操作任务继承同一修复。

回归测试对静态候选精确计数，用扩展静态区间的最大重叠数约束每个动态几何体在任何位置的候选数，再加动态配对上界、_sap_range的额外条目，以及nsweep游标增量。5×10配置的保守int32游标上界约19.49亿，低于21.47亿。原配置在新增测试中失败，修复后64项单元测试通过。该测试不依赖特定机器人姿态。

此前的小规模smoke测试会缩小地形，因此未覆盖这个规模相关缺陷。详细数值见 [诊断记录](dreamwaq-sap-diagnosis.json)。

## 服务器同规模重训验证

在用户确认后，已停止原运行并保留旧日志和模型；服务器64项测试通过，原四项完成任务记录逐项一致。新训练仍使用4096个环境、5000轮，实际保存的env.yaml确认网格5×10、初始level0。后续AMP和两项操作任务保持队列顺序。

同为第50轮时，原运行总奖励-1683.15、linear_z为-112.5776；修复后分别为-0.60、-0.0149。新运行到116/5000轮时总奖励-0.02，最近100轮均值-0.5153，速度约47756步/秒，并已保存model_0.pt、model_50.pt、model_100.pt。该同规模对照支持碰撞计数溢出的归因，尚不代表策略收敛或步态达标。
